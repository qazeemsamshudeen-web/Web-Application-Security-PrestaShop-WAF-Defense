1. Executive Summary

In modern e-commerce, web applications store sensitive consumer details, authentication secrets, and payment records. If left exposed without layered defenses, common flaws like injection and insecure default settings can lead directly to system compromise.

This laboratory simulates an enterprise assessment on a real-world web application: PrestaShop 1.7.8.9. Using Kali Linux and Burp Suite, we first demonstrated that an unshielded origin server processed dangerous Cross-Site Scripting (XSS) inputs without rejection. We then implemented a two-fold defense strategy: internal application hardening (directory obfuscation, installer removal, and configuration auditing) and an external Apache ModSecurity Web Application Firewall (WAF) running as a reverse proxy with the OWASP Core Rule Set (823 active rules) plus customized detection rules.

Upon retesting, the WAF dropped all malicious payloads at the perimeter, returning an HTTP 403 Forbidden status and preventing attacks from reaching the core application.

2. Architecture & Network Topology

The testing environment was configured on an isolated host-only network across two virtual machines:

  • Kali Linux (10.0.0.3): Functions as the attacker workstation running Burp Suite for request interception and payload injection.
  • Ubuntu Server (10.0.0.5): Hosts the Dockerized database (MySQL 5.7 on port 3306), the PrestaShop container (origin port 8080), and the Apache reverse proxy with ModSecurity (WAF gatekeeper on port 80).

3. Deliverable 1: Attack and Defense Evidence

Phase 1 — Vulnerable Baseline (Port 8080)

Direct requests sent to the Docker origin container (port 8080) bypassed any perimeter firewall. Injecting <script>alert('XSS-PRESTASHOP-POC')</script> into the search parameter s resulted in an unrestricted HTTP/1.1 200 OK response.

Phase 2 — WAF Defense Verification (Port 80)

When the identical payload was routed through the Apache reverse proxy on port 80, ModSecurity inspected the parameters in Phase 2 and instantly blocked the request:

  • Response Status: HTTP/1.1 403 Forbidden
  • Defense Outcome: The request was terminated before reaching the PrestaShop application container.

1000004 Installer Lockdown ^/install/ Denies access to leftover installation wizards to prevent store re-initialization.

Information Disclosure Risk Analysis

During the audit of /admin632wbv39e/.../system-information, the server reported: Apache/2.4.54, PHP 7.4.33, and MySQL 5.7.44. Exposing software versions enables attackers to cross-reference known CVE vulnerabilities. Production configurations must suppress headers using ServerTokens Prod and ServerSignature Off.

7. Key Recommendations for Production

  1. Port Isolation: Restrict origin port 8080 from direct external network access (allow only 127.0.0.1).
  2. SSL Termination: Bind a valid SSL/TLS certificate to the Apache reverse proxy on port 443.
  3. Virtual Patching Workflow: Utilize ModSecurity custom rules for zero-day mitigation prior to core CMS updates.
  4. PHP Runtime Upgrade: Migrate from end-of-life PHP 7.4 to an actively supported release (PHP 8.1+).
