Phase 2: Baseline Vulnerability Exploitation (Without WAF)

2.1 DVWA Baseline Attack Execution

Baseline testing against Damn Vulnerable Web Application (DVWA) on Port 8080 established unshielded application vulnerability:

  1. SQL Injection (SQLi):
    • Target URL: http://10.0.0.5:8080/vulnerabilities/sqli/
    • Injected Payload: ' OR '1'='1
    • Result: Application executed raw boolean-based bypass, returning HTTP 200 OK and dumping all database users (admin, gordonb, 1337, pablo, smith).
  2. Cross-Site Scripting (Reflected XSS):
    • Target URL: http://10.0.0.5:8080/vulnerabilities/xss_r/?name=<script>alert('XSS-DVWA-POC')</script>
    • Result: Unsanitized input rendered directly in DOM; JavaScript popup dialog executed with HTTP 200 OK.

Phase 3: Web Application Firewall (WAF) Engineering

3.1 ModSecurity v2.9 & OWASP CRS Installation (Ubuntu Host)

# Install Apache2 and ModSecurity engine
sudo apt-get update
sudo apt-get install -y apache2 libapache2-mod-security2

# Enable required Apache reverse proxy and security modules
sudo a2enmod proxy proxy_http headers security2 unique_id

# Deploy OWASP ModSecurity Core Rule Set (CRS v3.3.8)
sudo apt-get install -y modsecurity-crs
sudo cp /etc/modsecurity/modsecurity.conf-recommended /etc/modsecurity/modsecurity.conf

# Activate ModSecurity enforcement mode
sudo sed -i 's/SecRuleEngine DetectionOnly/SecRuleEngine On/' /etc/modsecurity/modsecurity.conf

3.2 Custom Virtual Patching Ruleset (prestashop_custom_rules.conf)

Created tailored Layer 7 rules located at /etc/modsecurity/prestashop_custom_rules.conf:

# RULE 1000001: Reflected/Stored XSS Prevention (Search bar & form inputs)
SecRule ARGS|REQUEST_COOKIES|REQUEST_HEADERS "@rx (?i)(<script[^>]*>.*?</script>|<script|javascript:|onload=|onerror=|alert\(|<svg[^>]*onload)" \
    "id:1000001,phase:2,deny,status:403,log,msg:'[DEFENSE BLOCKED] Cross-Site Scripting (XSS) Attack Detected',severity:CRITICAL"

# RULE 1000002: SQL Injection Prevention (UNION SELECT, OR 1=1, Comment truncation)
SecRule ARGS|REQUEST_URI "@rx (?i)(\b(union(\s+all)?\s+select|select.*from|insert\s+into|drop\s+table)\b|--\s*|'\s*or\s*'1'='1|'\s*or\s*1=1)" \
    "id:1000002,phase:2,deny,status:403,log,msg:'[DEFENSE BLOCKED] SQL Injection (SQLi) Signature Detected',severity:CRITICAL"

# RULE 1000003: Directory Traversal & Sensitive File Exposure
SecRule REQUEST_URI|ARGS "@rx (?i)(\.\./\.\./|etc/passwd|config/settings\.inc\.php|\.env|\.git)" \
    "id:1000003,phase:1,deny,status:403,log,msg:'[DEFENSE BLOCKED] Directory Traversal or Sensitive File Access',severity:CRITICAL"

# RULE 1000004: Restrict Installation Directory Exposure
SecRule REQUEST_URI "@rx (?i)^/install(/.*)?$" \
    "id:1000004,phase:1,deny,status:403,log,msg:'[DEFENSE BLOCKED] PrestaShop Installer Access Prohibited',severity:CRITICAL"

3.3 Reverse Proxy Gateway Configuration (/etc/apache2/sites-available/000-default.conf)

Configured Apache on Port 80 to terminate outside traffic, inspect transactions, and proxy clean traffic to container 8080:

<VirtualHost *:80>
    ServerAdmin webmaster@localhost
    DocumentRoot /var/www/html

    # ModSecurity Engine Activation
    SecRuleEngine On
    IncludeOptional /etc/modsecurity/prestashop_custom_rules.conf

    # Reverse Proxy to PrestaShop Docker Container
    ProxyPreserveHost On
    ProxyPass / http://127.0.0.1:8080/
    ProxyPassReverse / http://127.0.0.1:8080/

    # Restrict Secret Admin Path to Authorized Management IP
    <Location /admin47140aj33>
        Require ip 10.0.0.99
    </Location>

    ErrorLog ${APACHE_LOG_DIR}/error.log
    CustomLog ${APACHE_LOG_DIR}/access.log combined
</VirtualHost>
# Test Apache configuration syntax and reload service
sudo apache2ctl configtest
sudo systemctl restart apache2

Phase 6: Production Transition Architecture

Why Two Ports Were Used During Assessment

  • Port 8080 (Vulnerable Origin): Essential during testing to prove vulnerabilities existed in unshielded application code.
  • Port 80 (WAF Gateway): Essential to validate that ModSecurity actively filters payloads before proxying clean traffic.

Hardening Blueprint: Eliminating Public Port 8080

In enterprise production environments, origin application ports are strictly hidden:

  1. Localhost Loopback Binding: Re-bind Docker container ports to listen exclusively on 127.0.0.1:8080, making it invisible to outside network interfaces.
  2. Host Firewall Enforcement: 
    sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw deny 8080
sudo ufw enable
  3. Secure Management Tunnels: Developers requiring direct origin access connect via encrypted SSH port forwarding: 
    ssh -L 8080:127.0.0.1:8080 blaqqsec03@10.0.0.5
